# Архитектура и структура проекта StreamDesk

Документ описывает устройство проекта: структуру каталогов, технологический стек,
назначение модулей и зависимости между ними.

StreamDesk — это веб-приложение для команд, которые занимаются мероприятиями и стримами.
В одном месте собрано: склад оборудования, задачи (канбан), проекты, сметы, схемы
подключения и мониторинг компьютеров. В системе одновременно может работать несколько
компаний, при этом данные разных компаний не пересекаются (мультиарендность).

Приложение состоит из трёх основных частей: серверной (`backend/`), клиентской
(`frontend/`) и общего кода со схемой данных (`shared/`).

## 1. Структура каталогов

Основные каталоги и их содержимое (примерно 2 уровня вложенности):

```text
StreamDesk/
├── backend/            серверная часть на Express
│   ├── index.ts        точка входа, запуск сервера
│   ├── routes.ts       все маршруты API (очень большой файл)
│   ├── database.ts     инициализация и работа с базой
│   ├── storage.ts      типы и интерфейс слоя хранения данных
│   ├── db.ts           подключение к базе через Drizzle
│   ├── auth.ts         хеширование и проверка паролей
│   ├── seed-data.ts    тестовые данные для разработки
│   ├── vite.ts         подключение Vite и раздача собранного фронтенда
│   ├── yougile.ts      клиент внешнего сервиса YouGile
│   ├── yougile-sync.ts фоновая синхронизация YouGile с базой
│   ├── ip-checker.ts   проверка доступности компьютеров
│   ├── terminal-log.ts и terminal-access.ts  логи сервера и доступ к вкладке Терминал
│   ├── services/       внешние сервисы (телеграм, генерация документов, транскрипция)
│   └── types/          дополнительные типы для TypeScript
│
├── frontend/           клиентская часть на React
│   ├── index.html      основной HTML-шаблон
│   ├── public/         иконки, manifest, service worker (для PWA)
│   └── src/
│       ├── main.tsx    точка входа React
│       ├── App.tsx     маршруты и провайдеры
│       ├── pages/      страницы приложения (29 экранов)
│       ├── components/ компоненты (ui, dashboard, forms, layout и др.)
│       ├── hooks/      пользовательские хуки (websocket, toast, i18n и др.)
│       ├── lib/        вспомогательные функции
│       └── contexts/   контекст авторизации
│
├── shared/
│   └── schema.ts       описание всех таблиц базы (общее для фронта и бэка)
│
├── scripts/            агенты мониторинга (.ps1, .sh) и утилиты для базы
├── docs/               документация (в основном на русском языке)
├── tmp-drizzle/        служебные файлы миграций Drizzle
│
├── Dockerfile          сборка docker-образа приложения
├── docker-compose.yml  запуск базы PostgreSQL и приложения
├── package.json        зависимости и команды запуска
├── vite.config.ts      настройка сборки фронтенда
├── drizzle.config.ts   настройка миграций базы
└── README.md           описание проекта
```

В корне проекта также находятся `.bat`-файлы для запуска агентов под Windows
(`agent-computer.bat`, `agent-server.bat`, `agent-vmix.bat`) и тестовые скрипты для
проверки подключения к базе (`test-db.mjs`, `test-db-connection.js`).

## 2. Технологический стек и версии

Версии приведены по файлу `package.json`.

### 2.1. Клиентская часть (Frontend)

- React 18.3 и TypeScript 5.6 — основа интерфейса;
- Vite 5.4 — сборка и dev-сервер;
- Wouter 3.3 — маршрутизация на стороне клиента;
- TanStack React Query 5.60 — запросы к серверу и кеширование данных;
- Tailwind CSS 3.4 и компоненты на Radix UI — оформление и UI-элементы;
- Recharts 2.15 — графики мониторинга и статистики;
- Konva 9.2 / react-konva — холст для схем подключения;
- jsPDF, pdfkit, docx — экспорт документов (сметы, схемы);
- jsbarcode и html5-qrcode — генерация и сканирование штрихкодов.

### 2.2. Серверная часть (Backend)

- Node.js 20 и Express 4.21 — рантайм и веб-сервер;
- ws 8.18 — WebSocket для обновлений в реальном времени;
- Passport, passport-local, express-session — авторизация и сессии;
- Drizzle ORM 0.39 — работа с базой данных;
- zod 3.24 — валидация входящих данных;
- bcryptjs — хеширование паролей; multer — загрузка файлов;
- helmet и express-rate-limit — заголовки безопасности и ограничение запросов.

### 2.3. База данных

- PostgreSQL 16 — основная база данных;
- драйверы: postgres 3.4 (локальный сервер) и @neondatabase/serverless 0.10 (Neon);
- drizzle-kit 0.30 — применение схемы и миграции.

### 2.4. Сборка и развёртывание

- esbuild — сборка серверной части в `dist/`;
- tsx — запуск TypeScript в режиме разработки;
- Docker и docker-compose — контейнеризация и развёртывание;
- PM2 — альтернативный способ запуска в продакшене (`ecosystem.config.cjs`).

### 2.5. Команды запуска

| Команда | Назначение |
|---------|-----------|
| `npm run dev` | запуск в режиме разработки |
| `npm run build` | сборка клиентской и серверной частей |
| `npm start` | запуск собранного приложения |
| `npm run check` | проверка типов TypeScript |
| `npm run db:push` | применение схемы к базе данных |
| `npm run db:verify` | проверка подключения к базе |

## 3. Назначение модулей

### 3.1. Серверная часть (`backend/`)

- **index.ts** — точка входа. Инициализирует базу, подключает маршруты и обработчик
  ошибок, в разработке подключает Vite, в продакшене раздаёт статику. Выбирает порт
  (по умолчанию 5000, при занятости перебирает следующие) и запускает фоновую
  синхронизацию YouGile.
- **routes.ts** — содержит все маршруты API: авторизация, компании и приглашения,
  склад, задачи и проекты, сметы, схемы подключения, мониторинг и агенты, vMix, чат
  с ИИ, уведомления и транскрипция. Это самый объёмный файл проекта.
- **database.ts** — инициализация хранилища. Поддерживает режим «заглушки»: при
  отсутствии базы приложение всё равно запускается с пустыми данными.
- **storage.ts** — типы и интерфейс слоя данных (операции чтения и записи сущностей).
- **db.ts** — подключение к базе через Drizzle; поддерживает Neon и обычный PostgreSQL.
- **auth.ts** — хеширование паролей через bcrypt и проверка хешей.
- **seed-data.ts** — заполнение базы тестовыми данными и создание администратора
  в режиме разработки.
- **vite.ts** — интеграция Vite в режиме разработки и раздача собранных файлов
  в продакшене; вспомогательные функции логирования.
- **yougile.ts** — клиент внешнего API YouGile (ограничение — 50 запросов в минуту).
- **yougile-sync.ts** — фоновая односторонняя синхронизация данных из YouGile в базу
  с очередью и повтором при ошибках.
- **ip-checker.ts** — проверка доступности компьютеров и систем (ping).
- **terminal-log.ts / terminal-access.ts** — хранение последних логов сервера и
  управление доступом к вкладке «Терминал».
- **services/** — отдельные внешние сервисы:
  - `telegram-bot.ts` и `telegram-gateway.ts` — телеграм-бот и отправка уведомлений;
  - `document-generator.ts` — генерация документов в форматах PDF и DOCX (например, сметы);
  - `whisper-x-client.ts` — клиент сервиса транскрипции аудио (WhisperX).
- **types/express.d.ts** — расширение типов Express (поля сессии и пользователя).

### 3.2. Общий код (`shared/`)

- **schema.ts** — описание всех таблиц базы (39 таблиц) через Drizzle и схемы валидации
  zod. Файл используется и сервером, и клиентом, чтобы типы данных совпадали. Таблицы
  сгруппированы по областям: пользователи и компании, склад оборудования, задачи и
  проекты, схемы подключения, стримы и vMix, чат с ИИ, уведомления, а также копии
  данных из YouGile.

### 3.3. Клиентская часть (`frontend/src/`)

- **main.tsx / App.tsx** — запуск React и маршрутизация. Приватные страницы обёрнуты в
  `ProtectedRoute`, который не пускает на них без авторизации.
- **pages/** — экраны приложения (29 страниц): вход, онбординг, дашборд, склад,
  компьютеры, задачи, проекты, сметы, схемы подключения, мониторинг, стримы, настройки
  и другие.
- **components/ui/** — базовые элементы интерфейса на Radix UI (кнопки, диалоги, таблицы
  и т.д.), около 47 компонентов.
- **components/dashboard/** — виджеты главной страницы (статус оборудования и систем,
  быстрые действия, календарь, статистика).
- **components/forms/** — формы создания и редактирования (оборудование, событие, система).
- **components/layout/** — каркас интерфейса: шапка, боковое меню, футер, нижнее меню
  для мобильных устройств.
- **components/connection-schemas/** — холст схем подключения на Konva и диалоги к нему.
- **components/equipment/** — генератор штрихкодов, сканер и загрузка фотографий.
- **hooks/** — пользовательские хуки: `use-websocket` (обновления в реальном времени),
  `use-toast`, `use-i18n`, `use-mobile` и другие.
- **lib/** — вспомогательные функции: `queryClient` (настройка React Query), `auth`,
  `i18n`, `mojibake` (исправление неправильной кодировки текста), работа со штрихкодами
  и правами доступа к складу.
- **contexts/auth-context.tsx** — хранит данные текущего пользователя по всему приложению.

### 3.4. Скрипты и агенты (`scripts/`)

- **streamdesk-agent.ps1** и **streamdesk-agent-linux.sh** — программы-агенты, которые
  устанавливаются на компьютеры и отправляют на сервер их состояние: имя хоста, IP,
  загрузку CPU, память, диск, GPU и список процессов. Каждый агент привязан к компании.
- **create-db-if-missing.js** и **fix-env-database-url.js** — служебные утилиты для базы.

### 3.5. Инфраструктура и конфигурация

- **Dockerfile** — двухэтапная сборка образа: сначала сборка приложения, затем лёгкий
  образ для запуска. При старте сначала применяется схема базы, затем запускается сервер.
- **docker-compose.yml** — поднимает PostgreSQL 16 и приложение, пробрасывает порт 5000,
  база ждёт готовности через healthcheck.
- **drizzle.config.ts, vite.config.ts, tailwind.config.ts, tsconfig.json** — настройки
  миграций базы, сборки фронтенда, стилей и TypeScript соответственно.

## 4. Зависимости между модулями

### 4.1. Общий поток данных

```text
Браузер (React)
   │  запросы /api/... и WebSocket
   ▼
Сервер (backend/index.ts → routes.ts)
   │
   ├── база данных (database.ts, Drizzle) → PostgreSQL
   ├── YouGile (yougile.ts + yougile-sync.ts)
   ├── телеграм / WhisperX / ИИ (services/)
   └── агенты на компьютерах отправляют сюда своё состояние
```

### 4.2. Связи модулей

- Клиентская часть (`App.tsx`) использует страницы, страницы используют компоненты,
  а данные загружаются через `lib/queryClient` (React Query) по адресам `/api/...`.
- Обновления в реальном времени идут через WebSocket: хук `use-websocket` на клиенте
  и библиотека `ws` на сервере.
- Клиент и сервер берут типы данных из общего файла `shared/schema.ts`.
- На сервере `index.ts` подключает `routes.ts`, базу, Vite и синхронизацию YouGile.
- `routes.ts` обращается к базе (`database.ts`), авторизации (`auth.ts`) и сервисам,
  а входящие данные проверяет zod-схемами из `shared/schema.ts`.
- `yougile-sync.ts` получает данные из YouGile через `yougile.ts` и сохраняет их в базу.
- Агенты из `scripts/` отправляют состояние на сервер по адресу `/api/agents/heartbeat`.
- Docker собирает приложение, поднимает PostgreSQL и применяет схему через `drizzle-kit`.

### 4.3. Внешние сервисы

Внешние сервисы (YouGile, телеграм, ИИ, SSL) подключаются по желанию через переменные
окружения в файле `.env`. Без них приложение продолжает работать в базовом режиме.

| Сервис | Где используется | Переменные окружения |
|--------|------------------|----------------------|
| PostgreSQL | `db.ts`, `database.ts` | `DATABASE_URL` |
| YouGile | `yougile.ts`, `yougile-sync.ts` | `YOUGILE_API_KEY`, `YOUGILE_COMPANY_ID` |
| ИИ (Hugging Face) | маршруты чата и смет | `HUGGINGFACE_API_KEY`, `HUGGINGFACE_MODEL` |
| Telegram | `services/telegram-*` | токен бота в `.env` |
| HTTPS / SSL | `index.ts` | `SSL_CERT_PATH`, `SSL_KEY_PATH` |
| Сессии | авторизация | `SESSION_SECRET` |
