# 🔄 Автоматический деплой StreamDesk на Ubuntu сервер

## 📋 Обзор

Эта инструкция описывает настройку автоматической синхронизации файлов с вашего Windows компьютера на Ubuntu сервер при каждом обновлении.

---

## 🎯 Варианты автоматического деплоя

### Вариант 1: Через rsync (Рекомендуется для локальной разработки)

**Преимущества:**
- Быстрая синхронизация только измененных файлов
- Работает напрямую с вашего компьютера
- Не требует Git репозитория

**Недостатки:**
- Требует ручного запуска скрипта
- Нужен SSH доступ к серверу

### Вариант 2: Через Git + GitHub Actions

**Преимущества:**
- Полностью автоматический деплой при push в репозиторий
- История изменений
- Работает из любого места

**Недостатки:**
- Требует Git репозиторий
- Нужна настройка GitHub Actions

### Вариант 3: Через Git Hooks (автоматический при push)

**Преимущества:**
- Автоматический деплой при push
- Не требует внешних сервисов

**Недостатки:**
- Требует настройки bare репозитория на сервере

## 🚀 Вариант 1: Деплой через rsync (Пошаговая инструкция)

### Шаг 1: Подготовка сервера

Выполните все шаги из `DEPLOY_UBUNTU.md` до шага 9 (запуск приложения).

### Шаг 2: Настройка SSH ключей (для автоматического доступа)

**На вашем Windows компьютере:**

1. Откройте Git Bash или PowerShell
2. Сгенерируйте SSH ключ (если еще нет):

```bash
ssh-keygen -t rsa -b 4096 -C "your_email@example.com"
# Нажмите Enter для всех вопросов (или укажите пароль)
```

3. Скопируйте публичный ключ на сервер:

```bash
ssh-copy-id username@your-server-ip
# Введите пароль один раз
```

Теперь вы сможете подключаться без пароля!

### Шаг 3: Создание скрипта деплоя на сервере

**На сервере Ubuntu:**

```bash
cd /var/www/streamdesk
nano deploy-to-server.sh
```

Скопируйте содержимое из файла `deploy-to-server.sh` (см. ниже)

Сделайте исполняемым:

```bash
chmod +x deploy-to-server.sh
```

### Шаг 4: Создание скрипта деплоя на Windows

**На вашем Windows компьютере:**

Создайте файл `deploy-to-server.bat` в корне проекта.

Откройте файл и измените настройки в начале:

```batch
set SERVER_USER=ваш_пользователь
set SERVER_IP=IP_адрес_сервера
set SERVER_PATH=/var/www/streamdesk
```

### Шаг 5: Использование

**Каждый раз, когда вы обновляете файлы:**

1. Дважды кликните на `deploy-to-server.bat`
2. Скрипт автоматически:
   - Синхронизирует файлы на сервер
   - Установит зависимости
   - Соберет клиент
   - Перезапустит приложение через PM2

## 🔄 Вариант 2: Деплой через Git + GitHub Actions

### Шаг 1: Создание GitHub репозитория

1. Создайте репозиторий на GitHub
2. Загрузите ваш код:

```bash
git init
git add .
git commit -m "Initial commit"
git remote add origin https://github.com/your-username/StreamDesk.git
git push -u origin main
```

### Шаг 2: Настройка GitHub Secrets

1. Перейдите в Settings → Secrets and variables → Actions
2. Добавьте секреты:
   - `SERVER_HOST` - IP адрес вашего сервера
   - `SERVER_USER` - имя пользователя на сервере
   - `SERVER_SSH_KEY` - приватный SSH ключ (содержимое файла `~/.ssh/id_rsa`)

### Шаг 3: Создание GitHub Actions workflow

Создайте файл `.github/workflows/deploy.yml`:

```yaml
name: Deploy to Server

on:
  push:
    branches:
      - main

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Deploy to server
        uses: appleboy/ssh-action@master
        with:
          host: ${{ secrets.SERVER_HOST }}
          username: ${{ secrets.SERVER_USER }}
          key: ${{ secrets.SERVER_SSH_KEY }}
          script: |
            cd /var/www/streamdesk
            git pull origin main
            npm install --production
            cd client
            npm install
            npm run build
            cd ..
            pm2 restart streamdesk
```

### Шаг 4: Использование

Теперь каждый раз, когда вы делаете `git push`, изменения автоматически деплоятся на сервер!

## 🔧 Вариант 3: Деплой через Git Hooks

### Шаг 1: Настройка bare репозитория на сервере

**На сервере:**

```bash
cd /var/www
git clone --bare /path/to/your/repo.git streamdesk.git
# Или создайте новый bare репозиторий:
mkdir streamdesk.git
cd streamdesk.git
git init --bare
```

### Шаг 2: Создание post-receive hook

```bash
nano /var/www/streamdesk.git/hooks/post-receive
```

Содержимое:

```bash
#!/bin/bash

WORK_TREE=/var/www/streamdesk
GIT_DIR=/var/www/streamdesk.git

cd $WORK_TREE || exit
git --git-dir=$GIT_DIR --work-tree=$WORK_TREE checkout -f
git --git-dir=$GIT_DIR --work-tree=$WORK_TREE clean -fd

cd $WORK_TREE
npm install --production
cd client
npm install
npm run build
cd ..

pm2 restart streamdesk
```

Сделайте исполняемым:

```bash
chmod +x /var/www/streamdesk.git/hooks/post-receive
```

### Шаг 3: Настройка локального репозитория

**На вашем компьютере:**

```bash
git remote add production username@your-server-ip:/var/www/streamdesk.git
```

### Шаг 4: Использование

```bash
git push production main
```

Изменения автоматически применятся на сервере!

## 📝 Дополнительные настройки

### Настройка автоматических бэкапов

Создайте скрипт на сервере:

```bash
sudo nano /usr/local/bin/backup-streamdesk.sh
```

```bash
#!/bin/bash
BACKUP_DIR="/var/backups/streamdesk"
DATE=$(date +%Y%m%d_%H%M%S)
mkdir -p $BACKUP_DIR

# Бэкап базы данных
sudo -u postgres pg_dump streamdesk > $BACKUP_DIR/db_$DATE.sql

# Бэкап файлов
tar -czf $BACKUP_DIR/files_$DATE.tar.gz /var/www/streamdesk/uploads

# Удаление старых бэкапов (старше 7 дней)
find $BACKUP_DIR -type f -mtime +7 -delete
```

Добавьте в crontab:

```bash
crontab -e
# Добавьте строку (бэкап каждый день в 3:00)
0 3 * * * /usr/local/bin/backup-streamdesk.sh
```

## 🆘 Решение проблем

### Проблема: rsync не работает

```bash
# Проверьте SSH подключение
ssh username@server-ip

# Проверьте права доступа
ls -la /var/www/streamdesk
```

### Проблема: GitHub Actions не деплоит

1. Проверьте логи в GitHub Actions
2. Убедитесь, что секреты настроены правильно
3. Проверьте SSH ключ на сервере

### Проблема: Git Hook не выполняется

```bash
# Проверьте права на файл
ls -la /var/www/streamdesk.git/hooks/post-receive

# Проверьте логи
tail -f /var/log/syslog
```
