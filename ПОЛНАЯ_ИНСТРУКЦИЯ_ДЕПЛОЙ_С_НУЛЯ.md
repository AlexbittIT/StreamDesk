## 🎯 ШАГ 1: ПОДКЛЮЧЕНИЕ К СЕРВЕРУ ПО SSH

### 1.1. Подключение с Windows компьютера

**Вариант A: Через PowerShell (встроен в Windows 10/11)**

1. Откройте PowerShell (нажмите `Win + X` и выберите "Windows PowerShell")
2. Введите команду:
   ```powershell
   ssh username@IP_адрес_сервера
   ```
   Например: `ssh root@192.168.1.100` или `ssh user@45.67.89.123`
3. При первом подключении появится предупреждение - введите `yes` и нажмите Enter
4. Введите пароль (при вводе пароль не отображается - это нормально!)
5. Нажмите Enter

**Вариант B: Через PuTTY (если PowerShell не работает)**

1. Скачайте PuTTY: https://www.putty.org/
2. Установите и запустите PuTTY
3. В поле "Host Name" введите: `IP_адрес_сервера`
4. Порт: `22`
5. Нажмите "Open"
6. Введите логин и пароль

**Вариант C: Через WinSCP (для загрузки файлов)**

1. Скачайте WinSCP: https://winscp.net/
2. Установите и запустите
3. Заполните:
   - Host name: `IP_адрес_сервера`
   - User name: `ваш_логин`
   - Password: `ваш_пароль`
4. Нажмите "Login"

### 1.2. Проверка подключения

После подключения вы должны увидеть что-то вроде:
```
Welcome to Ubuntu 22.04 LTS
username@server:~$
```

Это означает, что вы успешно подключились! 🎉

## 🗄️ ШАГ 3: УСТАНОВКА И НАСТРОЙКА БАЗЫ ДАННЫХ POSTGRESQL

### 3.1. Установка PostgreSQL

```bash
# Установка PostgreSQL и дополнительных компонентов
sudo apt install -y postgresql postgresql-contrib

# Запуск PostgreSQL
sudo systemctl start postgresql

# Включение автозапуска при перезагрузке сервера
sudo systemctl enable postgresql

# Проверка статуса (должно быть "active (running)")
sudo systemctl status postgresql
```

**⚠️ ВАЖНО:** Обратите внимание на правильное написание: `postgresql` (не `posgresql` и не `postgres`)

**Что такое PostgreSQL?**
Это система управления базами данных, где будут храниться все данные вашего приложения (пользователи, оборудование, события и т.д.)

### 3.2. Создание базы данных и пользователя

**ВАЖНО: Замените `ваш_надежный_пароль` на реальный пароль! Используйте сложный пароль (минимум 12 символов, буквы, цифры, символы)**

```bash
# Переключение на пользователя postgres
sudo -u postgres psql
```

После этой команды вы увидите приглашение вида:
```
postgres=#
```

Это означает, что вы вошли в консоль PostgreSQL. Теперь выполните следующие команды **по одной**:

```sql
-- Создание пользователя для базы данных
CREATE USER streamdesk_user WITH PASSWORD 'ваш_надежный_пароль';

-- Создание базы данных
CREATE DATABASE streamdesk OWNER streamdesk_user;

-- Предоставление всех прав пользователю
GRANT ALL PRIVILEGES ON DATABASE streamdesk TO streamdesk_user;

-- Разрешение создавать базы данных (может понадобиться)
ALTER USER streamdesk_user CREATEDB;

-- Выход из PostgreSQL
\q
```

**⚠️ ВАЖНО:**
- Замените `ваш_надежный_пароль` на реальный пароль (запомните его!)
- После команды `\q` вы вернетесь в обычный терминал

**Пример хорошего пароля:** `MyStr3@mD3sk2024!`

### 3.3. Проверка создания базы данных

```bash
# Подключение к базе данных для проверки
sudo -u postgres psql -d streamdesk -c "SELECT version();"
```

Если вы видите версию PostgreSQL - всё отлично! ✅

### 3.4. Настройка доступа к базе данных

```bash
# Открываем конфигурационный файл PostgreSQL
sudo nano /etc/postgresql/*/main/pg_hba.conf
```

Найдите строки, которые начинаются с `local` и `host`, и убедитесь, что они выглядят так:

```
local   all             all                                     peer
host    all             all             127.0.0.1/32            md5
host    all             all             ::1/128                 md5
```

Если нужно изменить, используйте стрелки для навигации, отредактируйте, затем:
- Нажмите `Ctrl+O` (сохранить)
- Нажмите `Enter` (подтвердить)
- Нажмите `Ctrl+X` (выйти)

```bash
# Перезапуск PostgreSQL для применения изменений
sudo systemctl restart postgresql
```

### 3.5. Проверка подключения к базе данных

```bash
# Попытка подключения с созданным пользователем
psql -U streamdesk_user -d streamdesk -h localhost
```

Введите пароль, который вы указали при создании пользователя. Если подключение успешно, вы увидите:
```
streamdesk=>
```

Введите `\q` для выхода.

**Если не получается подключиться:**
- Проверьте, что вы правильно ввели пароль
- Убедитесь, что PostgreSQL запущен: `sudo systemctl status postgresql`
- Проверьте логи: `sudo tail -f /var/log/postgresql/postgresql-*-main.log`

## 🌐 ШАГ 8: НАСТРОЙКА NGINX (ВЕБ-СЕРВЕР)

### 8.1. Установка Nginx

```bash
# Установка Nginx
sudo apt install -y nginx

# Запуск Nginx
sudo systemctl start nginx

# Включение автозапуска
sudo systemctl enable nginx

# Проверка статуса

```

### 8.2. Создание конфигурации для вашего домена

```bash
# Создание конфигурационного файла
sudo nano /etc/nginx/sites-available/streamdesk
```

Вставьте следующую конфигурацию (замените `streamdesk.ru` на ваш домен):

```nginx
# Редирект HTTP на HTTPS
server {
    listen 80;
    listen [::]:80;
    server_name streamdesk.ru www.streamdesk.ru;

    # Редирект на HTTPS
    return 301 https://$server_name$request_uri;
}

# HTTPS сервер
server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name streamdesk.ru www.streamdesk.ru;

    # Пути к SSL сертификатам (будем настраивать позже)
    # Пока закомментировано - раскомментируем после установки SSL
    # ssl_certificate /etc/ssl/certs/streamdesk.ru.crt;
    # ssl_certificate_key /etc/ssl/private/streamdesk.ru.key;

    # Настройки SSL (раскомментируем после установки SSL)
    # ssl_protocols TLSv1.2 TLSv1.3;
    # ssl_ciphers HIGH:!aNULL:!MD5;
    # ssl_prefer_server_ciphers on;

    # Максимальный размер загружаемых файлов (для транскрибации)
    client_max_body_size 500M;

    # Логи
    access_log /var/log/nginx/streamdesk-access.log;
    error_log /var/log/nginx/streamdesk-error.log;

    # Проксирование на Node.js приложение
    location / {
        proxy_pass http://localhost:5000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
        
        # Таймауты для длительных операций транскрибации
        proxy_read_timeout 600s;
        proxy_connect_timeout 600s;
        proxy_send_timeout 600s;
    }

    # Статические файлы (загрузки)
    location /uploads {
        alias /var/www/streamdesk/uploads;
        expires 30d;
        add_header Cache-Control "public, immutable";
    }
}
```

**Сохранение:** `Ctrl+O`, `Enter`, `Ctrl+X`

### 8.3. Активация конфигурации

```bash
# Создание символической ссылки
sudo ln -s /etc/nginx/sites-available/streamdesk /etc/nginx/sites-enabled/

# Удаление дефолтной конфигурации (опционально)
sudo rm /etc/nginx/sites-enabled/default

# Проверка конфигурации на ошибки
sudo nginx -t
```

**Если видите "syntax is ok" и "test is successful" - всё отлично! ✅**

```bash
# Перезапуск Nginx

```

## 🔐 ШАГ 9: НАСТРОЙКА SSL СЕРТИФИКАТА

### Вариант A: Бесплатный SSL через Let's Encrypt (РЕКОМЕНДУЕТСЯ)

```bash
# Установка Certbot
sudo apt install -y certbot python3-certbot-nginx

# Получение SSL сертификата (замените домен на ваш)
sudo certbot --nginx -d streamdesk.ru -d www.streamdesk.ru
```

**Что произойдет:**
1. Certbot попросит ваш email - введите его
2. Согласитесь с условиями использования
3. Certbot автоматически настроит SSL и обновит конфигурацию Nginx
4. Сертификат будет автоматически обновляться каждые 90 дней

**Проверка автоматического обновления:**
```bash
sudo certbot renew --dry-run
```

### Вариант B: SSL сертификат от reg.ru (если уже куплен)

**Шаг 1: Загрузка сертификата на сервер**

Через WinSCP загрузите файлы сертификата:
- `certificate.crt` (или `.pem`)
- `private.key`

**Шаг 2: Установка сертификата**

```bash
# Создание директорий для сертификатов
sudo mkdir -p /etc/ssl/certs
sudo mkdir -p /etc/ssl/private

# Перемещение сертификатов (замените пути на реальные)
sudo cp /tmp/certificate.crt /etc/ssl/certs/streamdesk.ru.crt
sudo cp /tmp/private.key /etc/ssl/private/streamdesk.ru.key

# Установка правильных прав доступа
sudo chmod 644 /etc/ssl/certs/streamdesk.ru.crt
sudo chmod 600 /etc/ssl/private/streamdesk.ru.key
```

**Шаг 3: Обновление конфигурации Nginx**

```bash
sudo nano /etc/nginx/sites-available/streamdesk
```

Раскомментируйте строки с SSL (уберите `#` в начале):

```nginx
ssl_certificate /etc/ssl/certs/streamdesk.ru.crt;
ssl_certificate_key /etc/ssl/private/streamdesk.ru.key;

ssl_protocols TLSv1.2 TLSv1.3;
ssl_ciphers HIGH:!aNULL:!MD5;
ssl_prefer_server_ciphers on;
```

**Сохранение:** `Ctrl+O`, `Enter`, `Ctrl+X`

```bash
# Проверка конфигурации
sudo nginx -t

# Перезапуск Nginx
sudo systemctl restart nginx
```

## 🌍 ШАГ 10: НАСТРОЙКА DNS (ПРИВЯЗКА ДОМЕНА К СЕРВЕРУ)

### 10.1. Узнайте IP адрес вашего сервера

```bash
# На сервере выполните
curl ifconfig.me
```

Скопируйте IP адрес (например: `45.67.89.123`)

### 10.2. Настройка DNS записей в панели управления доменом

**Если домен на reg.ru:**

1. Войдите в панель управления reg.ru
2. Перейдите в раздел "Домены" → "Управление DNS"
3. Найдите ваш домен `streamdesk.ru`
4. Добавьте или измените A-записи:

```
Тип: A
Имя: @ (или оставьте пустым)
Значение: IP_адрес_вашего_сервера (например: 45.67.89.123)
TTL: 3600

Тип: A
Имя: www
Значение: IP_адрес_вашего_сервера (тот же IP)
TTL: 3600
```

5. Сохраните изменения

**⏱️ Изменения DNS могут распространяться от 5 минут до 24 часов.**

### 10.3. Проверка DNS

**С вашего компьютера:**

```powershell
# В PowerShell
nslookup streamdesk.ru
ping streamdesk.ru
```

Должен показаться IP адрес вашего сервера.

## 🛠️ РЕШЕНИЕ ТИПИЧНЫХ ПРОБЛЕМ С БАЗОЙ ДАННЫХ

### Проблема 1: "Connection refused" или "Cannot connect to database"

**Решение:**

```bash
# Проверка, запущен ли PostgreSQL
sudo systemctl status postgresql

# Если не запущен - запустите
sudo systemctl start postgresql

# Проверка подключения
psql -U streamdesk_user -d streamdesk -h localhost
```

**Если не подключается:**

```bash
# Проверка файла .env
cat /var/www/streamdesk/.env | grep DATABASE_URL

# Убедитесь, что формат правильный:
# DATABASE_URL=postgresql://streamdesk_user:пароль@localhost:5432/streamdesk
```

### Проблема 2: "password authentication failed"

**Решение:**

```bash
# Пересоздание пароля пользователя
sudo -u postgres psql

# В консоли PostgreSQL:
ALTER USER streamdesk_user WITH PASSWORD 'новый_пароль';

# Выход
\q

# Обновление .env файла с новым паролем
nano /var/www/streamdesk/.env
# Измените пароль в DATABASE_URL

# Перезапуск приложения
pm2 restart streamdesk
```

### Проблема 3: "database does not exist"

**Решение:**

```bash
# Создание базы данных заново
sudo -u postgres psql

# В консоли PostgreSQL:
CREATE DATABASE streamdesk OWNER streamdesk_user;
GRANT ALL PRIVILEGES ON DATABASE streamdesk TO streamdesk_user;

# Выход
\q
```

### Проблема 4: "permission denied" или "access denied"

**Решение:**

```bash
# Проверка прав пользователя
sudo -u postgres psql -d streamdesk

# В консоли PostgreSQL:
GRANT ALL PRIVILEGES ON DATABASE streamdesk TO streamdesk_user;
ALTER USER streamdesk_user CREATEDB;

# Выход
\q
```

### Проблема 5: Таблицы не создаются автоматически

**Решение:**

```bash
# Ручное создание таблиц через Drizzle
cd /var/www/streamdesk

# Если есть скрипт миграции
npm run db:push

# Или через SQL файл
sudo -u postgres psql -d streamdesk -f create_connection_schemas_tables.sql
```

### Проблема 6: База данных работает, но приложение не подключается

**Проверьте:**

1. **Формат DATABASE_URL в .env:**
   ```bash
   cat /var/www/streamdesk/.env | grep DATABASE_URL
   ```
   
   Должен быть формат: `postgresql://пользователь:пароль@хост:порт/база`

2. **Проверка подключения вручную:**
   ```bash
   psql -U streamdesk_user -d streamdesk -h localhost
   ```
   
   Если подключается - проблема в приложении. Проверьте логи:
   ```bash
   pm2 logs streamdesk --lines 100
   ```

3. **Проверка прав доступа к файлу .env:**
   ```bash
   ls -la /var/www/streamdesk/.env
   ```
   
   Должно быть: `-rw-------` (только владелец может читать)
